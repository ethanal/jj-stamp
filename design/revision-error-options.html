Keep navigation errors with navigation.

Four placement options · same failed ID, same unchanged diff · interactive UI sketches

01 · Inline validation Recommended

Keep the popover open. Put the failure directly under the field that caused it.

⚠ No change matches “aaaaaaa”.

02 · Inline with recovery guidance

Use the same placement, with a concrete next step for harder-to-explain failures.

⚠ This ID matches more than one change.

Enter a longer ID to select a single change.

03 · Dismissible toast

Close the popover. Keep a compact notification nearby, with a way back to the input.

⚠ Couldn’t open “aaaaaaa”.

No matching change found.

Enter a change or commit ID.

04 · Toolbar status

Leave a quiet, persistent failure indicator beside Go to. Click it to reveal details.

Couldn’t open “aaaaaaa”.

No matching change found.
Your current diff hasn’t changed.

Placement concepts only, not application changes. Examples distinguish “not found” from “ambiguous”; the UI should use the actual failure reason.
